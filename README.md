# Crystal — сайт детейлинг-центра

Статический сайт: чистый HTML + CSS + JavaScript без сборки, без npm и без
зависимостей. Двуязычный (русский / армянский), с подбором цены по VIN и
отправкой заявок в Telegram.

---

## ⚠️ ПРОЧТИТЕ ПЕРЕД ПУБЛИКАЦИЕЙ

**Сайт нельзя выкладывать в интернет в текущем виде.** Две причины, обе
обязательные к устранению:

1. **Юридические реквизиты заполнены наполовину.** Оператор Армении взят из
   выписки госреестра и стоит на месте (наименование, ՀՎՀՀ `28960983`,
   адрес регистрации, почта). А у российского оператора по-прежнему
   `[ЗАПОЛНИТЬ]` — название, ИНН, ОГРНИП, адрес. Публиковать политику
   конфиденциальности с половиной реквизитов — нарушение и российского
   152-ФЗ, и армянского Закона № ЗР-49 от 18.05.2015.
2. **Токен Telegram-бота утекает посетителям.** Пока
   `telegram.transport` стоит в `'direct'`, запрос уходит в `api.telegram.org`
   прямо из браузера, и токен бота виден любому в инструментах разработчика.
   Режим `'direct'` годится только для приёмки и демонстрации заказчику.

Отдельно, про админ-панель: её токен GitHub даёт право записи в репозиторий.
Он хранится только в `localStorage` того браузера, где вы его ввели, и в
репозиторий не попадает, но **саму `admin.html` не выкладывайте на
публичный адрес** — иначе любой, кто её откроет, сможет поменять контент
сайта на своём устройстве.

Полный чек-лист — в разделе [«Что сделать перед публикацией»](#что-сделать-перед-публикацией).

## Как запустить локально

Открывать `index.html` двойным щелчком **нельзя**: браузер заблокирует
ES-модули и `fetch` при схеме `file://`. Нужен любой локальный веб-сервер.

```bash
cd crystal-detailing
python -m http.server 8000
# открыть http://127.0.0.1:8000
```

Подойдёт и `npx serve`, и любой другой статический сервер.

## Настройка: файл `js/config.js`

Это **единственный файл**, который нужно править для настройки содержимого.
Всё, что требует заполнения, помечено строкой `[ЗАПОЛНИТЬ]` — найдите её
поиском по файлу, это исчерпывающий список.

Проверить, что осталось заполнить, можно командой:

```bash
node -e "import('./js/config.js').then(m=>console.log(m.listPlaceholders().join('\n')))"
```

Пока значение не заменено, сайт **не падает**: он показывает понятное
предупреждение и подсказывает, какого ключа не хватает.

### Телефон и адрес Армении

Заполнено по выписке из госреестра РА. В `CONFIG.branches.am` стоят два
**разных** адреса, и это не дубль:

| Ключ | Что это | Сейчас |
|---|---|---|
| `city` / `address` / `addressHy` | Где находится детейлинг-центр: его видит клиент, на него ведёт «Построить маршрут» | Ереван, ул. Арташисян, 81/1 |
| `legalAddress` / `legalAddressRu` | Адрес регистрации ИП по выписке. **В контактах не показывается** | Котайк, Абовян, Камарис 7, д. 17, индекс 2221 |
| `phone` | Телефон для показа | `+374 33-880-418` |
| `phoneRaw` | То же для ссылки `tel:` | `+37433880418` |
| `mapUrl` | Ссылка на карту | поиск по адресу на Google Maps |

⚠️ **Почему адрес продублирован.** Выписка из реестра даёт адрес, по
которому зарегистрирован предприниматель, а не адрес, куда приезжает
клиент. Сайт до этого показывал Арташисян 81/1 как точку сервиса.
Подменять один другим нельзя в обе стороны: клиент приедет на адрес
регистрации, где нет сервиса, либо в политике окажется адрес, которого нет
в реестре. Поэтому точка сервиса осталась в контактах, а адрес регистрации
ушёл в реквизиты. **Если заказчик скажет, что сервис находится по адресу
регистрации, — правьте `city`/`address`/`addressHy` и `CONFIG.legal.operatorAm.address`**,
и следите, чтобы в обоих местах был один текст.

Ссылка на карту — текстовый поиск, а не метка. Точные координаты здания по
выписке не получить, а выдуманная точка хуже честного поиска по адресу.
Пока это так, под карточкой висит пометка `contacts.placeholderNoteAm`
(«Ссылка на карту уточняется — пока это поиск по адресу»). Когда появится
точная метка — впишите её в `mapUrl` и уберите пометку из разметки
`index.html`.

`addressExtra` заполнять не обязательно — это вторая строка адреса
(этаж, ориентир), если она нужна.

Нужны политике конфиденциальности, согласию и cookie-политике. Источник —
выписка из **պետական միասնական գրանցամատյան** (госреестр РА), выписка от
12.11.2026. Заполнены:

| Поле | Значение | Откуда |
|---|---|---|
| `legal.operatorAm.name` | `Անհատ ձեռնարկատեր «Crystal»` | организационно-правовая форма из реестра + торговое имя |
| `legal.operatorAm.tin` | `28960983` | հարկ վճարողի հաշվառման համար (ՀՎՀՀ) |
| `legal.operatorAm.address` | Աբովյան, Կամարիս 7 փ., 17 տ., փ/դ՝ 2221 | հաշվառման վայր |
| `legal.operatorAm.email` | `mingay82@mail.ru` | էլեկտրոնային փոստ |
| `legal.operatorAm.activity` | `45.20.4` | вид деятельности; на страницы не выводится |

⚠️ **Из выписки намеренно не перенесено:** фамилия и имя владельца, дата
рождения, номер паспорта с подразделением и ՀԾՀ. Это персональные данные,
и политике они не нужны — хватает наименования, налогового номера и
адреса. Второе число из строки `28960983, 286.1626493` — номер дела
госрегистрации, а не налоговый номер, поэтому в `tin` его нет.

⚠️ **Страница реквизитов показывает значение на языке документа.** У
`name` и `address` есть пары `…Ru` (`nameRu`, `addressRu`), потому что из
реестра они пришли по-армянски: русскую политику нельзя заполнять
армянской строкой. Правило общее для всех полей, у которых в
`js/legal.js` есть суффикс в `LOCALIZED_REQUISITE_SUFFIX` — сейчас это
только эти два. Подпись поля тоже переводится, а вот значение
наименования остаётся на исходном языке.

**Осталось заполнить только российского оператора** (`legal.operatorRu`):
наименование, ИНН, ОГРНИП, юридический адрес и адрес для обращений. Пока
там заглушки, страницы `legal/*.html` показывают жёлтое предупреждение и
публиковать их нельзя. `legal.policyUpdated` тоже placeholder — дата
проставляется в день, когда исправлен весь пакет документов, а не только
армянская половина.

### Соцсети

`CONFIG.social.whatsapp`, `.telegram`, `.instagram`. Формат WhatsApp —
`https://wa.me/79155501777` (без плюса и скобок). Пока значение не
заполнено, кнопка в интерфейсе помечается неактивной, и посетитель не

⚠️ **Это единственное место, где незаполненное поле видно сразу.** Кнопки
мессенджеров стоят на первом экране, под заголовком: раньше они были в
подвале, а теперь это первые ссылки, к которым тянется посетитель. Пока
три поля выше пусты, все три кнопки приглушены и не нажимаются. Это
рабочее, но не лучшее состояние для главной страницы — заполните их
до публикации, они важнее любой другой настройки.

### Telegram: два чата

Заявки из России и из Армении уходят **в разные чаты** и не смешиваются.
Заполните `CONFIG.telegram.chats.ru.chatId` и `.am.chatId`. У супергрупп
id начинается с `-100`.

Как узнать id чата: добавьте бота в группу, отправьте туда любое сообщение
и откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе
будет `chat.id`.

### Режим цен

`CONFIG.pricing.priceMode` управляет тем, показываются ли на сайте числа.

- `'on-request'` — **текущий режим**. Вместо суммы везде выводится
  «Цена по запросу», а расчёт по VIN превращается в приглашение оставить
  заявку. Числа не публикуются нигде.
- `'fixed'` — показывать конкретные суммы из `CONFIG.pricing.services`.

Когда появится прайс: заполните `basePrice` реальными значениями и
переключите режим на `'fixed'`. Множители классов уже настроены и
проверены тестом, так что пересчитывать ничего не придётся — но цены
всё равно сверьте глазами.

> **Одна позиция в прайсе не подтверждена.** Услуга `polish` (полировка
> кузова) имеет цену 12 000 ₽ — это осмысленный пример, а не согласованная
> с вами цифра. В присланном прайсе её нет. Замените на реальную цену до
> перехода в режим `'fixed'`.

### Видео-фон главного экрана

`CONFIG.background` управляет роликом, который играет за первым экраном
(`#hero`). Фон стоит **только под первым экраном**, не под всей страницей:
ниже идут прайс-лист и форма, и движущаяся картинка под ними мешала бы
читать.

| Ключ | Что это |
|---|---|
| `enabled` | Главный выключатель. `false` — видео не загружается вообще |
| `video` | MP4/h264, ~3.8 МБ, 1920×1080, 30 с, без звука |
| `videoWebm` | WebM/VP9, тот же ролик легче (~2.6 МБ) |
| `poster` | Кадр-заглушка 1600×900 (99 КБ) |
| `posterMobile` | Вертикальный кроп 760×1080 (51 КБ) для телефонов |

**Чтобы поставить своё видео:** положите файлы в `assets/video/` и
поменяйте пути в `CONFIG.background`. Код трогать не нужно.

**Ролик сделан «палиндромом»**: 15 секунд вперёд, затем те же 15 секунд
назад. Поэтому последний кадр совпадает с первым, и петля `loop`
стыкуется без рывка. Если положить обычный ролик, на стыке будет
заметный скачок — либо сделайте такой же палиндром, либо смиритесь:

```bash
# развернуть ролик и склеить с исходным
ffmpeg -i in.mp4 -an -vf "reverse,trim=start_frame=1,setpts=PTS-STARTPTS" \
  -c:v libx264 -crf 21 -preset fast rev.mp4
ffmpeg -i in.mp4 -i rev.mp4 -filter_complex "[0:v][1:v]concat=n=2:v=1:a=0[out]" \
  -map "[out]" -c:v libx264 -crf 26 -preset slow -movflags +faststart out.mp4
```

**Видео грузится не всегда.** Тег `<video>` создаётся скриптом только
после проверок, поэтому в этих случаях скачается лишь постер (99 КБ
вместо 2.6 МБ):

- `CONFIG.background.enabled = false`;
- у посетителя включена системная настройка «уменьшить движение»;
- включена экономия трафика (`navigator.connection.saveData`
  или сеть `2g`/`slow-2g`);
- браузер не поддерживает ни один из форматов.

Проверено в браузере: при `enabled: false` в сетевых запросах нет ни
одного обращения к видеофайлу — только постер.

### Аналитика

`CONFIG.analytics.yandexMetrikaId` и `.googleAnalyticsId`. Счётчики
**не загружаются**, пока посетитель не нажал «Принять» в баннере cookie.
Это требование законов обеих стран, поэтому логика встроена в код, а не
оставлена на совесть настройщика.

## Что сделать перед публикацией

Отмечайте пункты по мере выполнения.

- [ ] **Развернуть serverless-функцию и перевести `telegram.transport`
      в `'proxy'`.** Функция `api/telegram.js` готова, токен живёт в
      переменных окружения хостинга. Пока `transport` стоит в `'off'`,
      форма честно сообщает, что приём заявок приостановлен. Пошагово —
      раздел «Безопасность: почему `'direct'` нельзя в продакшен».
- [ ] **Проверить доставку боевой заявкой.** После включения `'proxy'`
      отправьте одну заявку из формы с филиалом «Россия» и одну с
      филиалом «Армения» и убедитесь, что обе дошли до группы
      «Заказы с сайта».
- [ ] **Решить, нужен ли отдельный чат для Липецка.** Сейчас оба региона
      шлют в одну группу (`-5584341581`), регион различается первой
      строкой сообщения. Если заявки двух городов должны идти разным
      людям — заведите второй чат и поменяйте `chats.ru.chatId`.

## Безопасность: почему `'direct'` нельзя в продакшен

В режиме `'direct'` браузер посетителя отправляет заявку напрямую на
`api.telegram.org`, подставляя токен бота. Токен при этом **виден в
исходном коде страницы** и в инструментах разработчика — то есть любой
желающий может забрать его и писать в ваши чаты от имени бота, читать
чужие заявки или удалить бота.

Правильная схема — режим `'proxy'`:

```
браузер → ваша serverless-функция → api.telegram.org
```

Токен хранится в переменных окружения функции и на клиент не попадает.
Подойдёт любая платформа: Vercel, Netlify Functions, Cloudflare Workers,
Яндекс Облачные функции.

### Готовая функция: `api/telegram.js`

Функция уже написана и лежит в репозитории. Разворачивать её нужно
отдельно от самого сайта: сайт статический и живёт на GitHub Pages, а
функция — на платформе, которая умеет исполнять серверный код.

**Шаг 1. Переменные окружения.** Задаются в панели хостинга, не в файлах
репозитория:

| Переменная | Обязательна | Значение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | да | токен от `@BotFather` |
| `TELEGRAM_CHAT_RU` | нет | id чата для заявок из России |
| `TELEGRAM_CHAT_AM` | нет | id чата для заявок из Армении |
| `ALLOWED_ORIGIN` | нет | домен сайта для CORS, например `https://sargis7.github.io` |

Если `TELEGRAM_CHAT_RU`/`TELEGRAM_CHAT_AM` не заданы, используются id из
константы `DEFAULT_CHATS` в начале файла. **Токена в значениях по
умолчанию нет и быть не может** — это единственное, что обязательно
задавать вручную.

**Шаг 2. Размещение.** Для Vercel файл уже лежит по верному пути
(`api/telegram.js` → `/api/telegram`), достаточно `vercel deploy`. Для
Netlify Functions положите его как `netlify/functions/telegram.js` и
добавьте редирект `/api/telegram`. Для Cloudflare Workers оберните
экспорт: `export default { fetch: handler }`.

**Шаг 3. Включение на сайте.** В `js/config.js` две правки:

```js
transport: 'proxy',
proxyUrl: 'https://<ваш-проект>.vercel.app/api/telegram',
```

После этого форма начнёт отправлять заявки через функцию, а токен
останется на сервере.

### Что функция проверяет

Функция открыта в интернет, поэтому не доверяет ничему из запроса:

- **Чат выбирается только по `branch`** (`ru` или `am`) из белого списка.
  Поле `chatId`, если оно пришло в теле, игнорируется. Иначе через
  открытый адрес можно было бы рассылать сообщения в любые чаты от имени
  бота — это спам с вашего аккаунта.
- Тело ограничено 8 КБ, текст — 4096 символами (лимит Telegram), метод —
  только `POST`.
- `ALLOWED_ORIGIN` ограничивает CORS доменом сайта.
- Не чаще 5 заявок в минуту с одного адреса. Счётчик живёт в памяти
  процесса: на serverless он не делится между инстансами, поэтому это
  защита от случайного флуда, а не от целенаправленной атаки. Для
  строгого лимита нужен внешний счётчик (Upstash, KV) или rate limit
  самой платформы.
- Детали ошибок от Telegram уходят в `console.error`, а посетителю
  возвращается нейтральный код (`telegram_error`, `network`, `timeout`).

### Отдельный режим: `'off'`

Пока функция не развёрнута, в конфиге стоит `transport: 'off'`. В этом
режиме сайт честно показывает посетителю сообщение «Приём заявок через
сайт временно приостановлен» с телефоном и **не делает сетевых запросов
вообще**. Это не поломка и не заглушка на скорую руку: выключенная
доставка выглядит как выключенная доставка, а не как ошибка отправки,
которую посетитель не поймёт.

**Если токен уже использовался в публичном режиме `'direct'`** — считайте
его скомпрометированным. Отзовите через `@BotFather` (`/revoke`) и
выпустите новый.

В проекте есть все три реализации (`DirectTransport`, `ProxyTransport` и
заглушка `off` в `js/telegram.js`), поэтому переключение — это правка
одной строки в конфиге, а не переписывание кода.

### Проверки

```bash
node tools/test-routing.js        # маршрутизация, состав сообщения, режимы транспорта
node tools/test-api-telegram.js   # контракт serverless-функции, утечка токена
```

Второй набор подменяет `fetch` и в сеть не ходит — тестовые заявки в
боевую группу заказчика не попадают.

## Бренд: логотип и палитра

Визуальный стиль приведён к действующему сайту бренда
(`detailing-crystal.ru`). Оттуда взяты две вещи: **силуэт машины** как
знак и **цвета** — чёрная база, синий `#0074BA` и жёлтый `#F4DD5B`.

| Что | Где лежит | Для чего |
| --- | --- | --- |
| `assets/logo-mark.svg` | шапка | силуэт машины, светлый вариант под чёрный фон |
| `assets/logo-lockup.svg` | первый экран | полный логотип: машина + CRYSTAL + DETAILING |
| `assets/favicon.svg` | иконка вкладки и домашнего экрана | тот же силуэт на графитовой плите |
| `brand/_source-logo.png` | — | исходник с сайта бренда, не трогать |
| `brand/logo-*.png` | — | растры 256/512/1024 для мессенджеров и печати |

**Почему логотип не скопирован как есть.** В исходнике надпись CRYSTAL
белая: на тёмной шапке она видна, но на светлом фоне исчезает. Кроме
того, у силуэта машины тонкие линии — в шапке на 44 px они сливаются.
Поэтому знак идёт в светлом варианте (`brand/logo-mark-car-light.png`),
а в фавиконе силуэт дополнительно обведён контуром.

**Цвета.** Все они лежат в `:root` файла `css/style.css`, имена
`--c-lux*` сохранены специально: на них завязано 60+ правил и админка,
поэтому меняется значение, а не имя.

```css
--c-bg:      #000000;   /* было #0A0A0C */
--c-bg-alt:  #0B0B0B;
--c-surface: #0D0D0D;
--c-blue:    #0074BA;   /* новый: акцент логотипа, кнопки и ссылки */
--c-lux:     #F4DD5B;   /* было золото #C9A227 */
--c-gold:    #F4DD5B;   /* второй акцент, для цифр и меток */
--grad-lux:  linear-gradient(135deg, #2E96D8, #0074BA 48%, #005A91);
```

**Правило про жёлтый.** Жёлтым заливаются только небольшие элементы —
цена, метка раздела, звёздочка у обязательного поля. Крупные кнопки
синие: жёлтая заливка на чёрном читается как предупреждение, а не как
действие, и контраст с белым текстом у неё ниже.

Если цвета нужно поменять снова, правьте только блок `@layer tokens`
в `css/style.css` и `:root` в `css/admin.css`. Жёстко прописанных
`rgba(...)` старой палитры в проекте не осталось — проверяется так:

```bash
grep -rn "201, *162, *39\|#C9A227\|#E3C565" css/ || echo "чисто"
```

## Двуязычность

Русский и армянский. Язык определяется в таком порядке:

1. параметр адреса `?lang=hy` или `?lang=ru`;
2. сохранённый выбор посетителя;
3. язык браузера;
4. русский по умолчанию.

Переключение — без перезагрузки страницы. Тексты лежат в `js/i18n/ru.js`
и `js/i18n/hy.js`: словари плоские, ключи вида `'hero.title'`. **Оба
словаря обязаны содержать одинаковый набор ключей** — за этим следит
проверка `tools/check-i18n.js`.

Словарь — это база. Поверх него работают правки из админ-панели
(раздел «Тексты сайта»): `t()` сначала смотрит правку, потом словарь.
Пустая правка означает «вернуть исходное», а не «показать пустоту».

Чтобы добавить текст, в разметке ставят атрибут, а не пишут строку:

```html
<h2 data-i18n="services.title">Услуги</h2>
```

Доступные атрибуты: `data-i18n` (текст), `data-i18n-html` (безопасная
инлайн-разметка), `data-i18n-placeholder`, `data-i18n-aria`,
`data-i18n-title`, `data-i18n-content`, `data-i18n-value`,
`data-i18n-fallback` (текст на месте незаполненных данных из конфига,
например «Уточняется у заказчика»).

### Два правила, которые легко нарушить

**Словарь важнее конфига.** Если значение приходит из `js/config.js`
(`pricelist.details`, `branches.*.address`) и для него есть ключ в словаре,
проверять словарь нужно **первым**. Иначе армянская версия показывает
русский текст из конфига, хотя перевод существует и лежит рядом.
Именно так и было с описаниями услуг в прайс-листе: 9 подписей выводились
по-русски на армянской странице.

**Адреса.** У ереванского филиала есть поле `addressHy` — в армянской
версии улица пишется армянскими буквами (`Արտաշիսյան 81/1`), как в
`hero.badge` и `meta.description`. У Липецка такого поля нет и не нужно:
это российский адрес, и в армянской версии он справедливо остаётся
русским.

## Админ-панель

Открывается по адресу `admin.html` (например,
`http://127.0.0.1:8000/admin.html` при локальном запуске). Страница
помечена `noindex, nofollow` и не связана ссылками с сайтом, но это не
защита: отдельного пароля у неё нет, поэтому **не выкладывайте её на
хостинг**, если не готовы закрыть доступ средствами сервера
(Basic Auth, ограничение по IP). Панель рассчитана на компьютер
владельца, а не на публичный адрес.

### Что умеет

| Раздел | Что меняется |
| --- | --- |
| **Цены и услуги** | Цена и «зависит от класса» у каждой услуги; добавление и удаление услуг; порядок строк |
| **Прайс-лист** | Состав и порядок разделов прайса; примечание под таблицей и дата актуальности |
| **Тексты сайта** | Любая надпись на сайте, на русском и армянском |
| **Фотографии** | Ссылка на фото или загрузка файла с компьютера; порядок и удаление |
| **Филиалы** | Город, адрес, телефоны, карта; основной филиал; добавление и удаление |

Переключатель «Показывать цены на сайте» управляет режимом `priceMode`:
пока он выключен, и в прайсе, и в карточках услуг выводится
«по запросу», а цифры видны только вам в панели. Включайте его, когда
прайс согласован с заказчиком.

### Раздел «Тексты сайта»

Список всех 429 ключей обоих словарей. Ничего не нужно искать в коде:
нашли строку — исправили формулировку — она сразу видна на сайте.

1. Выберите **язык** (русский или армянский) — у каждого языка свои
   правки, русская строка не задевает армянскую и наоборот.
2. Найдите нужное поле: **поиск** ищет и по ключу (`hero.title`),
   и по самому тексту; **раздел сайта** сужает список до первого экрана,
   услуг, прайса, формы и т. д.
3. Правьте текст прямо в поле. Сохранение — через секунду после того,
   как вы перестали печатать, или сразу при уходе из поля.
4. **«Вернуть исходный»** на карточке отменяет правку одного ключа,
   **«Сбросить все тексты»** — всех сразу. Цены и фото при этом не
   трогаются: у текстов отдельный ключ хранилища.

Полезные подсказки в списке:

* бейдж **«Первый экран»/«Услуги»/…** — к какому разделу относится ключ;
* **«изменено»** слева на карточке — ключ отличается от исходника;
* **«пусто на армянском»** — перевода нет, сайт покажет русскую строку;
* если в исходной строке были подстановки `{name}`, `{price}`, `{date}`,
  `{n}`, они перечислены под полем. **Удалять их нельзя** — без них
  в тексте останется пустое место. Если подстановка пропала, поле
  подсвечивается красным и появляется бейдж «потеряно: {date}».

Список выводит **не более 120 строк за раз** ради скорости — этого хватает
с фильтрами, а над списком написано, сколько ещё скрыто. Пустое поле
означает «вернуть исходное», а не «показывать пустоту».

### Как это устроено и куда попадают правки

Правки сохраняются в `localStorage` браузера под ключом
`crystal_overrides` — это **дельта**, а не копия конфига: туда попадают
только те поля, которые вы реально изменили. Благодаря этому правки
`js/config.js` на сервере продолжают действовать везде, где их не
перекрыли в панели, а кнопка «Сбросить всё» — это удаление одного ключа.

Правки текстов лежат отдельно, в ключе `crystal_text_overrides`, по той же
логике дельты. Отдельный ключ нужен, чтобы «Сбросить все тексты» не
задевало цены и фотографии — это разные кнопки и разные разделы.

Сверху панели есть блок **«Публикация на сайте»**. Как только в нём указан
токен GitHub, каждая правка сразу уходит коммитом в репозиторий —
нажимать «сохранить и опубликовать» отдельно не нужно. Через минуту
изменение видят все посетители.

**Что именно коммитится.** Панель пишет один файл
`data/site-overrides.json` со списком изменённых полей. Страница при
загрузке читает этот файл и накладывает его поверх `js/config.js`. Так
сделано намеренно: если бы панель генерировала `js/config.js`, одна
опечатка в генераторе сломала бы сайт всем посетителям сразу. Битый JSON
же деградирует молча — страница просто покажет значения из `config.js`.

Отдельно про тексты: в файле они оказываются в разделе `texts`, и только
**изменённые** ключи — не весь словарь. Иначе при каждой публикации
в репозиторий уезжал бы снимок всех 429 строк, и новые переводы,
добавленные позже в `js/i18n/hy.js`, замирали бы за устаревшим снимком.
Формат такой:

```json
{
  "version": 1,
  "texts": {
    "ru": { "hero.title": "Детейлинг в Ереване" },
    "hy": { "hero.title": "Դեթեյլինգ Երևանում" }
  }
}
```

**Порядок применения:** `js/config.js` → `data/site-overrides.json`
(общие правки) → `localStorage` (ваши личные, ещё не опубликованные).
То есть серверные правки сильнее локальных, кроме режима цен: если вы
переключили `priceMode` уже после публикации, побеждает ваше переключение.

Для текстов сделано исключение: правки из репозитория **сливаются** с
локальными, и локальные побеждают. Причина простая — вы могли начать
править формулировку и не дождаться публикации; если бы серверный файл
перетирал локальное, работа пропала бы молча. Уже опубликованные строки
всё равно придут на сайт у всех остальных посетителей.

#### Настройка токена

1. GitHub → **Settings → Developer settings → Personal access tokens →
   Fine-grained tokens**.
2. Доступ только к репозиторию сайта, права — **Contents: Read and write**.
   Больше ничего не нужно.
3. Токен вставьте в поле в блоке «Публикация на сайте» и нажмите
   «Сохранить». Кнопка **«Проверить доступ»** скажет, всё ли в порядке.

⚠️ **Токен хранится в `localStorage` этого браузера и в репозиторий не
попадает.** Но он даёт право писать в репозиторий, поэтому: не заводите
панель на чужом или общем компьютере, не публикуйте `admin.html` на
хостинге, а если токен всё же утёк — отзовите его в GitHub и выпустите
новый. Отдельного пароля у панели нет.

Если токена нет или он неверный, правки **не теряются**: они остаются в
браузере, а панель честно пишет «Видны только в этом браузере». Кнопка
**«Загрузить из GitHub»** забирает текущее содержимое
`data/site-overrides.json` обратно в панель — удобно, чтобы продолжить
работу с другого компьютера.

**Панель только на русском.** Переключатель языка сайта на неё не влияет,
`admin.html?lang=hy` намеренно игнорируется: интерфейс панели не переведён
и переводить его не планируется.

## Проверочные скрипты

Запускаются без установки зависимостей, из корня проекта:

```bash
node tools/check-i18n.js        # словари согласованы, нет пустых ключей
node tools/check-pricing.mjs    # цены совпадают с прайсом (якорные точки)
node tools/check-wiring.mjs     # разметка ↔ скрипты ↔ стили ↔ словари
node tools/test-vin.js          # расшифровка VIN и расчёт (44 проверки)
node tools/test-routing.js      # выбор чата Telegram (23 проверки)
```

Что ловит `check-wiring.mjs`: селекторы в JS, которых нет в разметке;
ключи `data-i18n` в HTML, которых нет в словарях; вызовы `t('...')` с
несуществующим ключом; CSS-классы, которые JS добавляет, но которых нет
в стилях. Это самый полезный тест проекта — он находит рассогласования,
невидимые для проверки синтаксиса.

`check-i18n.js` также предупреждает, когда армянская строка заметно
длиннее русской. Предупреждение — не ошибка, но повод посмотреть на
вёрстку в армянской версии.

Правовые страницы собираются генератором:

```bash
node tools/build-legal-pages.mjs
```

Три страницы из четырёх генерируются из общего каркаса. `privacy-ru.html`
поддерживается вручную — у неё индивидуальный последний раздел.

## Как поменять содержимое, не сломав сайт

**Тексты** — тремя способами, по возрастанию усилий:

1. **Админ-панель → «Тексты сайта»** — для правки формулировок. Без кода,
   сразу на сайте. Рекомендуемый путь.
2. **`data/site-overrides.json`, раздел `texts`** — если нужно поправить
   строку с другого компьютера или без браузера владельца.
3. **Словари `js/i18n/ru.js` и `js/i18n/hy.js`** — для новых строк и
   переводов, которых в словарях ещё нет. Правьте оба сразу: после
   правки запустите `node tools/check-i18n.js`.

Правка из панели побеждает словарь, поэтому если строку исправили в
панели, а потом переписали в `ru.js`, — посетители увидят вариант из
панели. Проверяйте «Тексты сайта» с включённым фильтром
«Только изменённые», когда наводите порядок в словарях.

**Цены, услуги, фото, филиалы** — удобнее через админ-панель
(`admin.html`), но обязательно перенесите результат в `js/config.js`:
правки в браузере не видны посетителям (подробности — в разделе
«Админ-панель»). Править `CONFIG` руками тоже можно. Не вписывайте числа
в `index.html`: карточки услуг и прайс берут цену из конфига, а литерал
в разметке рано или поздно разойдётся с ними. После правки —
`node tools/check-pricing.mjs`.

**Телефоны, адреса, ссылки** — только в `CONFIG.branches`.

**Фотографии** — положить файлы в `assets/gallery/`, код менять не нужно,
если имена совпадают с ожидаемыми.

Порядок запуска модулей в `js/main.js` менять не следует: язык
устанавливается синхронно и до отрисовки, иначе армянский посетитель
увидит вспышку русского текста. Каждый модуль обёрнут в `safeInit`,
поэтому падение одного не лишает посетителя остальных.

## Поддержка браузеров

Современные Chrome, Firefox, Safari, Edge. Используются ES-модули
и `IntersectionObserver`, поэтому Internet Explorer не поддерживается —
и это осознанное решение, а не упущение.

## Лицензия и права на материалы

Код принадлежит заказчику. Фотографии работ и логотип заказчик
предоставляет сам и отвечает за право их публикации.

**Видео-фон** (`assets/video/`) добавлен по просьбе заказчика и
предназначен для **учебного проекта (диплом)**. Права на исходный
видеоматериал нужно подтвердить до публикации сайта в открытом доступе:
если ролик не ваш, замените его на собственную съёмку или на материал
с явной лицензией. Технически замена — это положить свои файлы в
`assets/video/` и поменять пути в `CONFIG.background`.
