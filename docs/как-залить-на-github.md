# Как залить сайт на GitHub

Репозиторий готов локально: ветка `main`, **три коммита**, 70 файлов,
7,7 МБ. Осталось два шага, которые нужно выполнить вам — они требуют
вашего токена GitHub, а у меня к нему доступа нет.

**Почему я не могу сделать это сам.** Подключённый коннектор GitHub
авторизован под аккаунтом `Sargis7`, но выдан с правами только на
чтение: попытка создать репозиторий возвращает
`403 Resource not accessible by integration`. Личных ключей на машине
тоже нет — ни токена, ни SSH-ключа, ни `gh` CLI. Поэтому создать
репозиторий и выполнить пуш может только владелец аккаунта.

## Шаг 1. Получить токен

Откройте <https://github.com/settings/tokens> → **Generate new token
(classic)** → отметьте галочку `repo` → Generate. Токен показывается
один раз, скопируйте его сразу.

## Шаг 2. Создать репозиторий

Откройте <https://github.com/new> и заполните:

| Поле | Значение |
|---|---|
| Repository name | `crystal-detailing` |
| Description | Crystal Detailing — двуязычный сайт детейлинг-центра (Ереван) |
| Visibility | **Public** (если нужны Pages) или Private |
| Initialize this repository with | **ничего не отмечать** |

Важно: не ставьте галочки на README, .gitignore и license. Иначе на
GitHub появятся файлы, которых нет локально, и первый же `git push`
будет отклонён как «несвязанные истории».

## Шаг 3. Отправить код

В терминале, из папки `crystal-detailing`:

```bash
git remote add origin https://github.com/Sargis7/crystal-detailing.git
git push -u origin main
```

Когда git спросит логин и пароль — логин `Sargis7`, а в поле пароля
вставьте токен из шага 1 (не пароль от аккаунта).

## Шаг 4. Включить GitHub Pages

Раздел **Settings → Pages** в репозитории:

- Source: `Deploy from a branch`
- Branch: `main`, папка `/ (root)`
- Save

Через минуту сайт откроется по адресу:

```
https://sargis7.github.io/crystal-detailing/
```

**Если Pages недоступны** — это нормально для приватного репозитория.
Бесплатный тариф GitHub отдаёт Pages только для публичных репозиториев.
Варианты:

1. Переключить репозиторий на публичный (Settings → General → Danger Zone
   → Change visibility) — тогда Pages заработают сразу;
2. Оставить приватным, а для показа сайта на защите запускать его
   локально (`python -m http.server` в папке проекта);
3. Захостить копию на Netlify, Vercel или Cloudflare Pages — все три
   умеют «подключить приватный репозиторий» и дают бесплатный адрес.

Файл `.nojekyll` уже в репозитории: он отключает обработку Jekyll,
которая иначе игнорирует файлы и папки с подчёркиванием в начале имени.

## Что уже сделано за вас

- три коммита: сайт целиком, инструкция по заливке, фотографии работ;
- `.gitignore` — из репозитория исключены `_shots/` (скриншоты проверки,
  десятки мегабайт) и временные файлы ffmpeg;
- `.gitattributes` — нормализация переводов строк, чтобы на Windows и
  Linux диффы не показывали «изменён весь файл»;
- проверено, что в репозитории нет секретов: токен Telegram и
  реквизиты — заглушки `[ЗАПОЛНИТЬ]`;
- проверено, что видео закоммичено байт в байт (3 795 208 и 2 627 816
  байт совпадают с файлами на диске).

## Что делать при следующих правках

```bash
git add -A
git commit -m "кратко, что изменилось"
git push
```

Pages пересоберутся сами примерно за минуту.
